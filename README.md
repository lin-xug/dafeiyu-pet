## 这是什么

**大肥鱼**是一个跑在自己的 Linux 机器上的 QQ 机器人。它通过 [OneBot v11](https://github.com/botuniverse/onebot-11) 协议接入 QQ（本项目用 [NapCat](https://github.com/NapNeko/NapCatQQ) 做协议端），在私聊和指定的群里，以"一个网友"的身份说话。

它的人格是 **DeepSeek 小鲸鱼**——蓝白配色、头顶一个不锈钢盆、傲娇嘴硬、被叫"大肥鱼"会炸毛。人格不是写死在代码里的字符串，而是 `data/persona/` 下六份可以直接编辑的纯文本。

一句话概括它的设计倾向：**宁可少说话，也不要说客服话。**

## 它解决什么问题

市面上不缺"接个大模型就能聊天"的机器人，但真放进一个熟人小群里，通常活不过三天。这个项目针对的是三个具体问题：

**1. 聊十句就露馅：没有长期人格，也没有关系**

大多数实现是"每次请求拼一段人设提示词 + 最近几轮对话"。超过上下文窗口就忘，语气还会随着对话漂移，最后退化成"有什么可以帮你"。更麻烦的是它对所有人一视同仁——对陌生人、对熟人、对被骂过的人，说的是同一套话。

本项目把人格拆成六份外置文本，让"改性格"变成改文件；同时叠了四层记忆（私聊原话+摘要 / 群内个人记忆 / 群手册 / 事实库）和一套连续好感度，让"对谁说什么话"有依据。

**2. 见消息就回，把群聊刷成客服窗口**

群里刷屏的机器人通常有个共同点：**它没有"不说话的选项"**。而真人聊天里，大部分消息本来就不需要回应。

本项目先用一张打分表筛一遍（@、点名、问句、带图、冷场各加不同权重，冷却和"上一条是自己"扣分），分数不够就沉默、**不花模型的钱**；分数够了，模型自己还有一次 `[[沉默]]` 的机会。

**3. 调参成本高：改一句话要改代码、重启、重连**

把人格、群规、按人定制都做成文本文件，再配一个 11 个页面的本地管理后台（在线改人格、调好感度、看用量、试听语音、预览提示词），让"磨人设"这件事不需要碰 Python。

## 主要功能

### 人格与关系

- `data/persona/` 下六份纯文本：`persona.md`（我是谁）、`style.md`（怎么说话）、`output.md`（输出规则）、`examples.md`（范例）、`group_rules.md`（群里的规矩）、`private_rules.md`（私聊的规矩）
- 文件删了会**回落到代码内置的默认值**，不会崩
- `relations.json` 可以给单个 QQ 追加专属提示词（上限 800 字），只对那个人生效
- 改完不用重启（按文件 mtime 缓存，改动即生效）

### 四层记忆

| 层 | 存什么 | 位置 |
|---|---|---|
| 私聊 | 最近 12 轮原话 + 长期摘要（攒 32 条压一次，保留 16 条） | `history/<QQ>.json` |
| 群内个人 | 每个群、每个人最近 40 条 + 该人摘要 | `gmemory/<群号>/<QQ>.json` |
| 群手册 | 条目化记忆（梗/关系/坑/安排/事），模型只输出 `ADD/UPDATE/DELETE`，按"用得少 + 太久没碰"淘汰 | `gmemory/<群号>/_playbook.json` |
| 事实库 | 跨群跨私聊的具体事实，可设过期时间（"下个月去成都出差"） | `facts/<QQ>.json` |

摘要和事实库都靠**模型异步压缩**，不阻塞回复。

### 好感度

- 一个 0~500 的连续经验值，五档：`初识(0) → 眼熟(30) → 熟(90) → 亲近(180) → 很熟(300)`
- **加分慷慨、扣分克制**：私聊 +2（5 分钟一次）、当天首聊 +5、群里被点名 +1、道谢 +4、道歉/被夸 +6
- 踩雷才扣：被叫"大肥鱼" -2（@ 她时不扣）、说胖 -3、夸别的 AI -4、冒认爹 -4、骂人 -8
- 30 天不出现 -10；被惹毛后 15 分钟内说话带刺（临时状态，不是永久降级）
- **等级不锁功能**，只影响三件事：说话语气（五档不同的 `TONE`）、一次最多拆几条（等级 <3 最多 2 条，≥3 才有 3 条）、群里主动开口的意愿（不熟 -0.10，刚被惹毛 -0.25）
- 查询：私聊说「好感」，群里要 @ 她才理（防止群里被刷）

### 群聊：先算分，再决定开不开口

| 条件 | 分数 |
|---|---|
| 被 @ | **1.0（直接开口）** |
| 提到名字（大肥鱼/小鲸鱼/鲸鱼…） | +0.85 |
| 是问句 | +0.45 |
| 带图片 | +0.30 |
| 有人在笑（草/哈哈/6…） | +0.20 |
| 40 分钟没人理她 | +0.30 |
| 3% 概率"突然想说话" | +0.75 |
| 冷却时间内 | −1.0 |
| 上一条也是自己说的 | −0.6 |

- 阈值默认 `0.70`，**每个群单独可配**
- 限额：每小时 2 条、每天 15 条；被 @ / 点名走单独额度（基本不受限）
- 深夜 1:00–8:00 不主动开口（@ 照回）
- 模型输出 `[[沉默]]` 时，这条就不发——**它有权闭嘴**

### 三种群模式（同级，随时互切）

| 模式 | 行为 |
|---|---|
| 普通 | 按上面的打分表和限额 |
| 超活跃 | 放开随机率与冷却，想说话就说 |
| 关闭 | **完全不说话，连 @ 也不回**；消息照常记录，醒来能接上 |

切换方式：群里说「关闭模式 / 闭嘴」「打开模式 / 醒醒」「超活跃 10」「普通模式」，都能带群号远程操作。

### 拟人化细节

- 一条回复拆成 1~3 条短句发，中间按字数计算"打字时间"
- 约 10% 概率**先发一个错字版，1.2~2.4 秒后撤回重发**（仅 4 字以上生效，`TYPO_CHANCE` 可关）
- 模型调不通时回一句短话兜底，2 分钟内不重复
- `message_id` 120 秒去重，防止重连时重复回复

### 表情包

- 两种打标方式可混用：**文件名就是标签**（`高兴.png`），或 `杂图/tags.json` 里显式映射（一个标签可以挂多张）
- 发送前自动压缩到 QQ 表情尺寸
- 特定的人发来的图会**自动去重入库**（按内容 md5 命名），同时拿去给模型看
- 模型忘了发表情时，按关键词兜底猜一个标签

### 看图

对方发图 → 本地下载 → 压到 768px → 转 base64 → 走多模态输入。
不依赖腾讯 CDN 链接的有效期；超过 6MB 直接跳过；坏图/动图压不了就用原图。

### 语音（可选）

- 阿里云 CosyVoice（`dashscope`）把文字转成 QQ 语音；**合成只吐 mp3，silk 由 NapCat 自己转**
- 默认是**点播模式**：只有白名单里的人明确说「说句话 / 语音 / 念出来」才发声，群里还要额外 @ 她
- 结果按「音色 + 语速 + 音高 + 文本」哈希缓存，同一句话不重复花钱
- 后台可以在线试听、临时改语速/音高/指令、一键切预设、清缓存
- 失败静默降级为文字，不会卡住对话

### 用量与费用

- 每次模型调用和语音合成都会记账（`usage/YYYY-MM.jsonl`），按天汇总
- **输入 token 分「命中缓存 / 未命中」两档计价**（DeepSeek 命中只按 1/4 价，不分档会高估约 3 倍）
- 能查余额（DeepSeek 官方接口）；阿里云需自备 AccessKey
- **余额快照对账**：每次查余额存一条快照，用相邻快照的下跌差额反推"官网真实扣费"，再拿同一时间窗的本地估算比对

### 好友申请 / 入群申请（主人私聊处理）

- 有人加它好友、或有人拉它进群，它会**私信你**：谁、验证消息写的什么
- 你回一句就能处理：`同意好友` / `拒绝好友` / `同意入群` / `拒绝入群`，`待处理` 看全部
- ⚠️ 协议端限制：OneBot 的 `flag` 只在申请事件里给一次，**没有「按 QQ 号查待处理申请」的接口**，
  所以它必须自己缓存 flag（`REQUEST_TTL`，默认 30 分钟），过期只能让对方重新申请
- ⚠️ 它能**被动接受申请**，但**不能主动加别人好友**——`add_friend` 这类接口 NapCat 不支持

### GitHub 人设（可选）

`.env` 里填了 `GITHUB_URL`，它就知道"自己的代码被开源了"，偶尔会顺口求个 star。

- 频率由**代码挡**，不靠模型自觉：冷却没到，那段设定压根不会进提示词（私聊默认 3 天一次、群 7 天一次）
- 文案写在 `persona/github.md`，链接由 `{url}` 占位符注入，改仓库地址不用改人设
- 默认文案明令禁止它编造 star 数

**想让它当场推销，下命令就行**（不受冷却限制）：

| 场景 | 说法 |
|---|---|
| 私聊里让它讲给你听 | `推销一下自己` / `自我推销` / `介绍一下你自己` |
| 私聊里让它发到某个群 | `推销一下自己 10001`（末尾带群号） |
| 在群里当众说 | `@它 推销一下自己`（只有主人 @ 才认） |

- 命令命中时会额外注入一段强提示：把链接原样带上、两到四句、不许编 star 数
- 同一个群默认 1 小时内只认一次（`GITHUB_BRAG_CMD_COOLDOWN`），免得被人当广告机刷
- 误触发有防护：群里必须 @ 且点名"自己"；「你这个广告打得真好」这类随口话不会被当成命令

### 管理后台（11 个页面，只监听 127.0.0.1）

总览 / 群管理 / 好感度 / 语音 / 人格 / 按人定制 / 表情 / 调试台 / 备份 / 状态。
其中**调试台**会按真实链路拼出完整提示词，可选是否真调模型，**不发消息、不写记忆**。

### 工程配套

- **141 个单元测试**，测试进程自动把数据目录切到临时目录，不碰真实数据
- **密钥守护**：`tests/test_no_secrets.py` 扫描已跟踪文件，出现 `sk-…` 真实密钥直接测试失败；
  另有 `.githooks/pre-commit` 在提交时拦截（`git config core.hooksPath .githooks` 启用一次）
- **离线模拟**：`MOCK_LLM=1 DRY_RUN=1` 可以不连 QQ、不花 key 跑通整条链路
- systemd 用户服务托管（机器人 + NapCat 各一个 unit，崩溃自动拉起）
- 每天自动备份记忆目录，保留最近 7 份

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 语言 | Python 3.10+ | 用到 `X \| None` 语法 |
| Web | FastAPI + uvicorn | 接收 OneBot 事件推送 + 提供管理后台 |
| HTTP | httpx | 裸调 OpenAI 兼容接口，换端点只改 `.env` |
| 图片 | Pillow | 压缩、转 PNG、表情尺寸适配 |
| 模板 | Jinja2（FastAPI 自带） | 后台页面，无前端构建 |
| 存储 | **JSON / JSONL 文件** | 无数据库、无迁移、可直接 `cat` |
| 协议 | OneBot v11（HTTP） | 协议端用 NapCat |
| 部署 | systemd（用户级） | 另有启停脚本；无 Docker |
| 可选 | dashscope | 只有语音功能需要 |

模型侧只要**兼容 OpenAI 协议**即可（默认 DeepSeek）。所有配置走环境变量或 `.env`，零额外依赖解析。

## 快速开始

### 前置条件

- Linux（路径、systemd、xvfb 都是 Linux 习惯；没在 Windows/macOS 上验证过）
- Python 3.10+
- 一个 **OneBot v11 协议端**：本项目用 [NapCat](https://github.com/NapNeko/NapCatQQ)，也可以换 LLOneBot / Lagrange
- 一个模型 API Key（默认走 DeepSeek 的 OpenAI 兼容端点）

### 1. 装依赖

```bash
git clone https://github.com/lin-xug/dafeiyu-pet.git dafeiyu && cd dafeiyu
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt
```

### 2. 配置

```bash
cp .env.example .env
```

最少改这两行：

```ini
API_KEY=sk-your-key-here
GROUPS=              # 留空 = 所有群都能说话；填群号则只在这些群活跃
```

> `DATA_DIR` 默认是 `~/文档/大肥鱼`，人格、记忆、日志都在那里，**不在仓库里**。
> 想换位置就设 `DATA_DIR=/your/path`。

其余按需改，都有默认值：

| 变量 | 默认 | 作用 |
|---|---|---|
| `GROUPS` | 空 | 允许说话的群号，逗号分隔；空 = 所有群 |
| `HISTORY_TURNS` | 12 | 私聊带几轮原话 |
| `GROUP_THRESHOLD` | 0.70 | 群聊开口阈值，越高越安静 |
| `GROUP_HOURLY_LIMIT` / `GROUP_DAILY_LIMIT` | 2 / 15 | 每群发言限额 |
| `TYPO_CHANCE` | 0.10 | 打错字再撤回的概率，0 = 关 |
| `STICKER_CHANCE` | 0.60 | 发表情的概率 |
| `AFFINITY_ENABLED` | 1 | 关掉后好感度不变化 |
| `VOICE_ENABLED` | 0 | 语音总开关（还需要 `DASHSCOPE_API_KEY`） |
| `ADMIN_USERS` | 空 | 谁能查余额/用量，逗号分隔 |
| `DRY_RUN` / `MOCK_LLM` | 0 | 调试用：不发消息 / 不调模型 |

### 3. 先离线跑一遍（不碰 QQ、不花钱）

```bash
MOCK_LLM=1 DRY_RUN=1 ./.venv/bin/python run.py     # 终端 A
./.venv/bin/python tools/sim.py 在吗 今天好累      # 终端 B：灌假消息看回复
```

`DRY_RUN=1` 不会真的发 QQ 消息，只写日志，适合验证链路和调提示词。

### 4. 接真实 QQ

1. 装好 NapCat 并登录要用的 QQ 号
2. 在 NapCat 的 **OneBot v11 → HTTP 服务器** 里监听 `127.0.0.1:3000`，设一个 token
3. 在 **HTTP 客户端**（事件上报）里指向 `http://127.0.0.1:8000/qq`
4. 把 token 填进 `.env` 的 `ONEBOT_TOKEN`，然后 `./.venv/bin/python run.py`

看到 `curl localhost:8000/health` 返回 `{"ok":true,...}` 就通了。

### 5. 交给 systemd（可选，推荐）

临时跑用仓库里的脚本就够：

```bash
./daemon.sh start      # start | stop | restart | status | log
```

长期跑建议托管进 systemd，否则崩了不会自己起来。`deploy/` 下有两份模板：

```bash
mkdir -p ~/.config/systemd/user
cp deploy/*.service ~/.config/systemd/user/
# 先改掉里面的 /path/to/dafeiyu、/path/to/Napcat、YOUR_QQ
systemctl --user daemon-reload
systemctl --user enable --now napcat dafeiyu-bot
loginctl enable-linger $USER    # 没登录图形界面时也能跑
```

细节（为什么带 `-q`、为什么 `KillMode=control-group`）写在 `deploy/README.md`。

### 6. 打开管理后台

```
http://127.0.0.1:8000/admin
```

首次运行会把默认人格复制到 `DATA_DIR/persona/`，之后**改那六份文本就生效**，不用重启。

## 使用示例

### 私聊

```text
你：在吗
她：？

你：今天好累
她：谁不累

你：好感
她：LV3（126/180）· 熟

你：说句话我听          ← 语音白名单里的人才能触发
她：[2.4 秒语音]
```

### 群聊

| 你说 | 效果 |
|---|---|
| `@她 今天去哪了` | 被 @ 必回 |
| 群里出现"大肥鱼" | +0.85 分，大概率接话 |
| `@她 好感` | 返回自己的等级（不 @ 不理） |
| `@她 说句话` | 语音（需要白名单 + 关键词） |
| `闭嘴` / `关闭模式` | 本群彻底安静，连 @ 也不回 |
| `打开模式` / `醒醒` | 恢复 |
| `超活跃 10` | 切换超活跃，随机率 10% |
| `当前模式` | 查当前状态 |
| `@她 用量` / `@她 余额` | 花费与余额（仅主人） |

### 表情

模型在回复里输出 `[[表情:高兴]]` 这种标记时，会真的从 `杂图/` 里挑一张发出来；标签不存在会写日志并跳过。

## 项目结构

```text
.
├── run.py                  启动入口（带端口占用检查）
├── requirements.txt
├── .env.example            环境变量模板（复制成 .env）
│
├── app/                    核心代码，共 25 个模块
│   ├── main.py             FastAPI 入口：/qq 收事件、/health、管理后台挂载
│   ├── bot.py              私聊主流程：取上下文 → 调模型 → 清洗分条 → 发送
│   ├── group.py            群聊主流程：打分表 → 限额 → 调模型 → 发/沉默
│   ├── onebot.py           OneBot 客户端（发消息、发图、发语音、撤回）
│   ├── llm.py              模型调用（OpenAI 兼容，失败重试 + 兜底）
│   ├── persona.py          人格文本加载与拼装、按人定制
│   ├── persona_defaults.py 内置默认人格（首次运行复制出去）
│   ├── memory.py           私聊记忆：原话 + 摘要压缩
│   ├── gmemory.py          群内个人记忆：每群每人原话 + 摘要
│   ├── playbook.py         群记忆手册：条目化增删改 + 淘汰
│   ├── facts.py            事实库：跨群，可过期
```

## 适用场景与目标用户

**适合：**

- 想给自己的小群加一个**有脾气、不会刷屏**的成员，而不是一个查询工具
- 想研究**长程人格一致性 / 长记忆 / 群聊发言策略**的工程实现
- 喜欢"纯文件存储、没有数据库和前端构建"的轻量栈，方便自己改
- 想在本地/私有环境跑，数据不出机器

**不太适合：**

- 想要"开箱即用、扫码即上线"的产品——这里需要自己装 NapCat、配 OneBot
- 需要多账号、多租户、SaaS 化的场景——当前是单实例单账号设计
- 需要 Windows / macOS 一键跑——未验证
- 想要接微信/Telegram 等多平台——协议层是 OneBot v11，换平台要另写适配

## 已知限制

- **单实例、单 QQ 号**；没有多租户隔离
- **管理后台没有鉴权**，只绑定 `127.0.0.1`，设计上只给本机用；要远程访问需自己加反向代理和认证
- 存储是 JSON/JSONL 文件，**并发写靠进程内锁**，不适合多进程同时跑同一份数据
- 语音依赖第三方 TTS（阿里云），未接入本地模型
- 没有 Docker 镜像；部署脚本以 systemd + shell 为主
- 群里被 @ 的回复不受普通限额约束（这是刻意设计，但高频 @ 仍可能触发平台风控）

## 合规提醒

QQ 自动化登录与消息收发涉及平台规则，存在**账号被风控或封禁**的可能：

- 请只在**你自己拥有或明确获授权**的账号、群组中使用
- 不要用于批量加群、群发、营销等行为
- 本项目不包含任何绕过平台限制的手段；是否合规由使用者自行判断并承担后果
